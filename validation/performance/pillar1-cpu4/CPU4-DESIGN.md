## One public ownership seam

`embedding::writes` is std-only and unconditional. `WriteDomain<R>::new(binding, limits)` returns the unique host domain and one non-Clone `WriteFactory<R>`. The factory opens bounded independent non-Clone ports fallibly after the domain moves to its actual host thread. It shares only registration/budget/closed state, never publish or close authority. Dropping/closing the domain permanently closes registration; leaked factories cannot revive it. A fixed weak registry has no ownership cycle. Registration and final-port destruction use its cold mutex; ordinary writes never acquire it.

`WriteBinding` contains exact group/incarnation, node and store/incarnation/session. `WritePort::begin(&mut self, &[WriteInput])` yields an affine submission and owned invocation. Submission extraction creates individual affine producers. Each producer binds once from an actual proposal LogEntry selected by the real host, and publish checks the actual committed command's full u128 operation, immutable bytes, term and index plus domain/port/epoch/generation/ordinal. OriginalEnvelope getters and invocation correlation retain every original identity; outcomes are Applied(position,R), NotSubmitted or Unknown(reason). DeliveryRejected owns the exact rejected R. No raw send, public ticket reconstruction or commit certificate is introduced. Public `try_take` does not install/cancel a waiter; `waiter` borrows the invocation mutably for one actively polled original per port.

`WriteDomain::validate_submission` checks opaque domain identity plus live scope/generation before extraction; numeric binding equality alone does not route a live submission between two domains. The Counter fixture accepts caller-supplied GroupIdentity for fresh groups and reuses only free live group slots; it is not a recovery constructor for an old incarnation.

The host still owns proposal admission, consensus progress, whole-interval application, receipt cardinality/order validation, fencing and recovery. A binding or caller-provided LogEntry does not certify commitment. All3 real application calls and owned receipt Vecs remain. The old StateMachine API and existing native ClientRouter/ApplicationRouter/EffectOwner/logical/durable paths remain release-source unchanged.

## Physical bounds and ownership

Construct a fixed cell Vec and bounded retained command buffers before admitting any write. Reserve each cell's selected command ceiling at construction, check actual Vec capacities, and reject construction exceeding command-capacity or retained-byte budgets. No payload growth is needed during begin; malformed/oversize input rejects before publication. This deliberately trades cold retained capacity for simpler peak accounting, rather than assuming growth is free. Empty commands use this same bounded path. Ordinary host/core input Vec copies remain, including their simultaneous overlap with retained immutable bytes and CommandBytes. No receipt-buffer API or shared-command core change.

Per-port charge uses concrete size_of values and actual capacities: PortShared/control/mutex + Arc header/alignment allowance, cell capacity*Cell<R>, retained payload capacities, opaque epoch/header, all bounded submission/invocation/producer/exported-envelope handles and epoch references, selected Waker ownership reserve, N*receipt nested reserve, plus declared simultaneous host handoff/output and command-copy/conversion reservations. Inline R is in Cell. Wrapper descriptor spare capacity is charged separately. Returned error R and exported R remain caller-owned output budget, not zero-cost deallocation. StateMachine Vec spare capacity/nested R and input-copy peaks coexist with cells and remain in the host ledger. Trusted standard allocator policy permits ordinary Arc/control allocation failure to follow the process allocator policy; no unsafe allocator counter or allocation-call claim.

Per-domain charge includes concrete registry/control/host/factory sizes and actual weak-slot capacity plus every live port reservation. Closed-but-held ports/producers/envelopes retain reservations until the last shared owner drops; request, deferred, PendingReplies, effect/core/log/application/snapshot queues retain their existing separate budgets. No lifetime throughput quota. Port capacity is caller-selected, never a public hardcoded4 maximum. Normal matched clients open configured batch capacity once; a larger previously supported invocation chooses the real owned channel path before admission, under unchanged Actor count/byte checks. The reusable path is used for ordinary configured workload and qualification adapter, never relabelled owned coverage.

## State and cleanup

Port Idle -> Published -> Draining -> Idle; Closed is terminal. A preparing begin publishes no handles until all checks succeed. Per cell producer Unextracted -> Extracted -> PositionBound -> Terminal; observation Open -> Ready -> Consumed, or Closed. Every live submission, invocation, producer and exported envelope has explicit bounded ownership. Reuse requires all old handles gone, producers terminal and observations consumed/discarded. Cancellation cannot release accepted ownership or roll back core/application. Drop of unextracted submission resolves NotSubmitted; accepted work with lost observation remains Unknown/ConsumerClosed according to real progress. Applied prefix survives later send/application/domain failures. Delivery rejection stops at the same original, returns its exact R, and leaves tail owners for actual teardown.

Generation increment is checked; test-only small maximum exercises exhaustion. Only fully quiescent reuse replaces the opaque epoch and resets the counter. Old scope/epoch/generation/ordinal never decrements a new owner's counts. Leaked owners cause BusyDrain within their finite reservation. Domain close scans its bounded registry and closes unresolved work, preserving already Applied. One domain never shuts down caller resources or another group.

All state tests and Waker registration happen under one per-port mutex. Clone candidate Waker first, then check readiness/install atomically; take old/matching Wakers and outputs for wake/drop after unlocking. Arbitrary R destruction and Waker clone/wake/drop occur outside locks, including cancellation, replacement, close and poison cleanup. Poison is recovered only to fence and resolve work; it never resumes successful publication or panics through unwrap cascades.

## Retirement sequencing, before the focused correction

The new-slice deterministic `producer_token_is_genuinely_retired_before_readiness_wakes_the_next_invocation` failed: wake synchronously consumed the result/finished its invocation, but begin observed BusyDrain because publish retained its affine producer until returning. Its exact inputs/log are preserved under cpu4-builder-r2 (producer-retirement-1). This is an implementation ordering defect within the planned port lifecycle, not permission to add pacing or weaken BusyDrain.

Internal owned handles will use a non-Clone Lease<Option<Key>>. Terminal producer publication and queued-submission drop retire their actual key and owner count under the same per-port mutex before exposing readiness/unlocking. A separate non-authorizing Shared Arc keeps the allocation alive while the old Key's Shared/Arc<()> epoch references are destroyed; neither can run R or Waker destruction there. Drop that temporary Arc and invoke/drop Wakers outside the mutex. A Lease Drop fallback retires genuine ownership during unwinding. Invocation/exported-envelope destruction uses the same consuming retirement; R is destroyed before its envelope lease. Closed/poisoned work preserves Applied and cannot resume. Drained reap also removes stale Waker registration for destruction outside lock. No public signature or consensus/application contract changes; all added temporary Arc reference operations/inline storage remain charged costs. Acceptance is the failed deterministic test becoming green plus all lifecycle/Counter/normal-consumer controls, including genuine pending-owner BusyDrain and quiescent epoch renewal.

Lint decomposition (same CPU4 milestone): strict matched checks found the existing create function exceeded 100 lines after adding cold registration. Test-only partition pumping and actual interval collection are factored without changing iteration order or assertions. No new runtime prerequisite, authority or allocation is added.
