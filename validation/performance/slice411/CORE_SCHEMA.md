# Slice 411 Core: admitted ordinary append / local-barrier overlap

Native worker already emits Written and wakes before store.barrier. The current Core emits its first follower Append only from After::LeaderAppend after local Durable. That serializes local synchronization before network+follower synchronization. This slice overlaps those existing steps; local commit synchronization remains required afterward.

API: Raft::admitted_replication_reservation()->Option<usize> is a pure pre-admission inspector; None means serialized/ineligible or no bounded opportunity. Raft::replicate_admitted(ticket)->Result<Vec<Effect>,RaftError> always begins with the unchanged admitted(ticket), then emits optional eligible early ordinary Append sends. Wrong/duplicate/fenced tickets retain original rejection. Original admitted and public raw worker helpers remain unchanged. Root owns physical EffectOwner opt-in/reservation/lease-continuation integration.

Eligibility: current established Leader/local voter; current-term committed durable tip (last==commit); unchanged hard state/ballot/group/generation and plain Delta ordinary pure append; all new entries Command, 1..64, no membership/snapshot/Noop/read/transfer/repair mutation. Each eligible follower has known durable matching progress at the durable tip and next_index=tip+1. Unknown/lagging peers and an outstanding bulk/snapshot request stay serialized.

Steady-state empty collector: an ordinary commit notification often leaves a zero-entry Append outstanding at that same committed tip. Blocking early output solely because this collector exists would miss common writes. Permit one such old EMPTY collector as a bounded alias of the new original request. Store its original context/config/start/end plus successor context. Never replace a bulk/snapshot collector, never extend an old window's end in place, never churn contexts on retries, never permit a second alias. Fresh early context owns the newly admitted range. Old alias scope remains valid only while its exact successor collector remains current.

State: exact pending ticket -> optional admitted range records (peer, fresh context, ticket) + optional empty alias -> local barrier succeeds -> same original collectors valid against durable bytes -> exact new ack -> normal durable matching/quorum/commit/application flow. Core.state/local progress/commit/application do not move from Written. Core.step remains Busy while pending; authenticated acks remain bounded queued events until local completion. A successful old empty ack only retires its alias and grants no new progress or commitment. New success retires both primary/alias. Configuration/term/election/compaction/failure clears every associated collector/tag/alias; recovery initializes none.

Ownership: pending already owns immutable staged bytes. Early frames clone only the bounded new suffix into owned messages. No retained log clone and no borrowed background buffers. Preflight counts actual eligible recipients and bounded new payload/entry metadata plus queued effect/request/alias metadata using checked arithmetic. Parent retains original continuation budget alongside this extra budget and queues terminal continuation behind early leased/queued sends. Additional budget unavailable means old serialized behavior.

Currentness: original request lookup by exact peer/context/config resolves either primary or its bounded empty alias. Ordinary range matching uses durable entries, or (only while the exact admitted ticket/context still belongs to this pending unit) immutable pending suffix entries. After local completion those same bytes/range match canonical durable state. No new ballot/read/snapshot authority derives from accepted data. Existing reply family/source/node/store/term/configuration matching remains required. Higher-term response handling retains its original path before ordinary correlation.

Failure: local append/barrier failure after early follower persistence fences old owner and retires local windows; no old-owner client success. Uncommitted follower suffix may legitimately be retained and committed by a future leader, so invocation outcome remains Unknown rather than NotProposed. Rejection/transport retry keeps original context and payload. Old aliases cannot validate a later replacement/restart/reconfigured request even if indices/content look alike.

Acceptance: exact Written callback starts real follower work while local Durable withheld; local state/progress/commit/results unchanged; premature missing/wrong/repeated ticket rejects; reservation bounds actual early outputs; held old empty collector remains scoped and its ack cannot retire new request; old/new ack order, rejection, higher term, failure, restart/compaction retirement; no bulk/snapshot/unknown-peer/Noop/config/logical optimization; original serial controls; actual three-voter commit and individual receipts only after original durable gates. Root validates terminal completion while early send queued/leased, shared-worker requests, budget fallback and end-to-end Linux/macOS.
