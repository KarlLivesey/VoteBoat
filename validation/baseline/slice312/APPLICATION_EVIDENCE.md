## Implemented contracts and ownership

One concrete `TransferApplication` has a checked coordinator or participant role. It implements all six existing application, bounded receipt, proposal admission, read, bounded read and checkpoint traits, without a wrapper or runtime. Immutable checked public IDs/spec/profile/ten phase IDs and exact group incarnations identify every command. The two participant groups have canonical order independent of debit direction; each transfer selects one account from each fixed configured group. Multiple bounded accounts and reverse direction are supported. Safe existing voter membership changes are permitted: proposal context validates the application's own group, without a configuration freeze.

Public commands encode business Start only; public queries expose account/status. Internal subsequent phase commands and encoders are private to the transaction subtree and intentionally represent trusted host-driver assertions, not authenticated foreign certificates. No user-provided ready flags or public proof-upload API was added. Original application-unit results provide the explicit proof premises in the tests; these unit histories are not native Node/quorum provenance qualification.

Coordinator progression is Started → Decided → AppliedAll → Finished, with exact immutable proofs, decisions and original phase outcomes retained. Participant Prepare records a planned balance and exclusive lock, or a durable business refusal, without changing balance. Commit applies once and holds the lock; Abort from Absent/Refused creates a complete retained tombstone, never acquires/releases another transaction's lock. Release removes only the original lock after the coordinator AppliedAll assertion. Late Prepare returns the original retained outcome or Closed(Abort), without resurrection. Account reads return Locked while owned work remains.

Receipt is compact and allocation-free: current invocation index, historical `first_index`, exact operation, semantic outcome and duplicate marker. Full original spec/status contains original phase positions, decisions, proofs and refusal assertions. A replayed duplicate's current index cannot replace its canonical first index when constructing identical dependent-phase bytes. The first index is zero only for an unretained binding conflict.

Lifetime bounds: configured transactions and accounts each range from 1 through 4096. No record/phase ID is evicted. Each participant must be provisioned by driver313 for at least the sole coordinator's whole lifetime N; the application exposes exact limits/account membership for that assembly check. Admission counts retained plus pending whole transaction bindings and all possible local phases, rejects conflicting exact command bytes and aliases. Coordinator Start reserves all ten phase IDs against existing and pending specs by exact destination, preventing a later participant alias from stranding work. Unknown coordinator phases require original Start binding (including pending Start); participant first intake is Prepare or Abort. Start N+1 refuses before phase work; exact retries/terminal phases remain available at N. Driver313 must preflight fixed account membership before committing Start; a proposal rejection is not business refusal.

Commands use exact 444-byte little-endian `VBTRCMD1`. Checkpoints use `VBTRCP01`, `TRANSFER_SCHEMA = 0x5642545200000001`, an exact 153-byte header, 40-byte accounts and 2309-byte complete transaction records. Enforced deployment snapshot bound is `153 + 40 * max_accounts + 2309 * max_transactions`, independent of current occupancy. The decode checks exact sizes/counts/tags/IDs/canonical empty fields before bounded allocations. Apply batches use temporary cloned state and publish only after every contiguous entry succeeds; Noop/Configuration advance the ordinary boundary without account effects or receipts.

Restore checks schema, own group/incarnation/profile/role/capacities, configured opening accounts and external applied boundary. Sorted unique records/IDs, globally unique nonzero first positions within the boundary, original immutable specs/commands/outcomes and aliases are checked. Original retained phase commands are reconstructed in first-position order from configured opening balances; no new foreign facts are synthesized. Full parsed accounts, locks, prepare arithmetic, tombstones, decisions/outcomes/positions and records must exactly equal reconstructed state before publication. Historical released balances are validated by replay, allowing subsequent legitimate transfers. No Noop materialization for applied-index gaps is required.
