# Independent bounded transaction protocol model

Owned files only: tests/transaction_model.rs and tests/transaction_model/. No production helpers, source/docs/manifest changes or git actions. This is the prerequisite protocol/model work for the proposed supported P8 two-participant transfer; it is not an implemented transaction feature or proof of a native engine.

Data: two immutable transaction IDs/amounts (5 and 7); two participant accounts with initial balances (20, 0); durable coordinator Started/Decided(Commit|Abort)/AppliedAll/Finished with exact committed phase proofs and first decision, plus separately owned volatile receipt observations; durable participant Absent/Prepared/DecisionApplied/Released with original prepare/refusal evidence, planned before/after account values and exclusive lock. Exploration begins after both durable Starts. Volatile typed commands/receipts occupy one slot per transaction, at most two messages total; sends require an empty slot. Participant and transaction IDs scope all facts; the model generator originates receipts only from a matching durable phase/content, with immutable transfer content implied by transaction ID. It abstracts committed/applied application commands, not Raft persistence/quorum/authentication proof.

Transitions: canonical participant acquisition, durable prepare/refusal, receipt delivery, Commit only with both exact prepares or Abort after a recorded refusal, decision application retaining locks, exact application acknowledgements, AppliedAll only after both, release only from AppliedAll, Finished only after both releases. Loss clears individual messages; restart clears all volatile messages and preserves durable facts/locks. Reconstructed source facts can be resent. Timeout is a baseline no-op, never a decision. Unknown observations and coordinator unavailability do not clear locks.

Independent acceptance oracle: stable coordinator decision; matching participant decision; prepared/decision-applied locks retained; no competing lock owner; no read of a locked account; release only after exact AppliedAll; coordinator phase/receipt evidence consistent; Finished only after both terminal releases; balance conservation whenever both accounts are observable. Explicit weakening modes allow premature release, participant timeout abort or unstable coordinator decision; each must produce an actual finite counterexample, not a success flag from the implementation under test.

Explore bounded reachable states with an 80-transition depth ceiling and 250,000-state ceiling, reporting visited states, edges, restart/loss actions, distinct states containing Finished(Commit)/Finished(Abort), both commits finished and a commit/abort pair finished, and whether any ceiling truncates search. The initial 40-step run truncated before both commits finished; parent inspection required raising only this depth/resource envelope. Stop at the explicit ceiling and report it honestly. No general liveness claim; separate terminal/resend and blocked-prefix controls demonstrate both successful commits, a contending commit/abort pair, insufficient funds, and receipt reconstruction after loss/restart when messages are eventually delivered. This is two accounts/two transfers with finite original IDs, not arbitrary participant counts, transaction programs, elastic ownership, external recipient atomicity or a formal full-engine proof. Production receipt provenance is root's trusted host-driver/Rust embedding path consuming original Node Applied completions/fresh quorum status; this independent model assumes that trusted origin and does not prove the native adapter.

Pre-edit refinement after root's ownership review: received observations are volatile, distinct from durable coordinator phase proofs. Prepared/refused observations exist only while Started; applied observations only while Decided; released observations only while AppliedAll. Restart clears observations plus wire slots. Decided commits the original observed prepare/refusal proof; AppliedAll commits the exact applied proof; Finished commits exact release proof. Each phase clears its now-unused collection. Durable original participant status regenerates lost observations. The oracle checks both collections' provenance separately; it must not treat receipt arrival as a durable coordinator command.
