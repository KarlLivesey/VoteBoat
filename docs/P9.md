## Minimum framework floor

Pinned OpenRaft reference: e88bb40707f2e511d8ecc44d31edcb1d814a11a8.
Its minimal benchmark has3 nodes, empty requests/responses, an in-memory BTree
log, a no-op application and function-call RPC. Published setup is MacM1-Max,
client runtime1 worker/server runtime16 workers,1024 warmup operations and a
default20 million operations rounded to complete equal client/batch workloads.
Each client waits for its write's applied result; batch4 consumes every result.
Rates count entries, not batch requests.

The user additionally requires passing OpenRaft with a healthy margin. Working
acceptance is at least1.5 times the larger of the published floor and the
matched sustained upstream rate in every required cell, on each supported host.
This is a minimum acceptance bar, not a performance target or stopping ceiling.
The user explicitly wants that sustained capacity and substantially more; keep
the measured optimization loop active beyond crossing an individual floor.
Use full-duration repeated runs with maintenance/catch-up active, exact original
results, bounded memory/debt, and reported latency/refusals; short medians do not
establish this margin. The table gives the minimum50% margin when the published
